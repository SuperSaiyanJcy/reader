# 设计说明

## 界面

以桌面 Word 的文档窗口为视觉参考：系统原生窗口控制、自绘标题区域、选项卡、功能区、水平标尺、灰色工作区、白色纸张和底部状态栏。业务交互集中在文件打开、正文排版、导航、查找、缩放和阅读规则。标题栏及其余装饰按钮保持静态。

标题栏固定使用通用的“文档1”名称，不泄露当前小说名；文件页显示真实文件信息。Esc 替换显示内容为工作汇报，不切换应用身份、不操作其他软件；小说位置保留在内存和本机记录中。

## 技术结构

- `electron/main.cjs`：系统文件选择器、受控文件读取、编码解码、最近记录与原生窗口。
- `electron/fonts.cjs`：TrueType 文件头与表边界校验、字体内容去重和安全标识。
- `electron/preload.cjs`：仅暴露固定的本地阅读 API；不把 Node.js 或通用 IPC 暴露给页面。
- `src/App.tsx`：阅读状态、快捷键、工作文档切换和进度保存。
- `src/components/`：功能区、文件页、导航、规则弹窗和虚拟正文。
- `src/lib/parser.ts`：逐行匹配目录、合成分节、按字符偏移分块。
- `src/workers/parser.worker.ts`：把大文本和正则处理从界面线程分离；超时终止。
- `src/lib/parseAsync.ts`：创建、取消和销毁独立工作线程。
- `src/lib/pageFlip.ts`：根据文本行的位置计算保留两行重叠内容的翻屏目标。
- `src/lib/fonts.ts`：用 FontFace API 校验与注册用户导入的字体，不安装系统字体。

Electron 页面开启 context isolation、sandbox，关闭 Node integration，拒绝外部窗口与导航、拒绝权限请求。使用受控 `reader://app/` 协议加载本地资源。文件读取只能来自系统选择器、已记录文件或内置示例。TXT 作为 React 纯文本渲染，不使用 HTML 注入。

## 目录方法与参考

阅读类软件通常维护多种 TXT 标题规则：中文章回卷、数字加分隔符、英文 Chapter、序章与后记等。项目以这一方法为参考，独立实现了较精简的预设，并让用户在预览后选择规则。

参考：

- [Legado 项目](https://github.com/gedoor/legado)：本地 TXT 标题规则分类的设计背景。
- [Legado Reader 分支的 txtTocRule.json](https://github.com/neighbourkiller/legado-reader/blob/main/app/src/main/assets/defaultData/txtTocRule.json)：用于了解中文、数字、英文与特殊标题等规则类别。本项目未复制该规则集。
- [Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)：隔离上下文、沙箱、权限与 IPC 边界。
- [Electron 自定义标题栏](https://www.electronjs.org/docs/latest/tutorial/custom-title-bar)：隐藏系统标题栏、保留原生窗口控制和可拖动区域。
- [electron-builder 架构说明](https://www.electron.build/docs/architecture/)：macOS arm64 与 Windows x64 目标。

## 排版与定位

小说解码后统一换行，以字符偏移作为稳定位置。修改字号或行距后重新分块，通过偏移恢复原文位置。正文页面和目录使用虚拟列表，长篇小说仅渲染视口附近内容。

分块用字符权重近似中西文字宽，以约 900 像素的文字高度生成虚拟渲染单元。所有单元拼接成连续白纸，不补齐固定页高，不在章节或卷边界强制分页，单元之间没有上下页边距、页脚或空白间隔。段落跨块时取消末块的段后间距，确保段落连续。虚拟列表同步测量真实高度与小数像素，避免字体与缩放变化引起接缝留白。这里的页数仅是内部参考分块数。普通滚动保存的是靠近视口上方的字符位置；目录跳转保存准确的章节起始偏移。

## 方向键翻读与字体

左侧窄工具栏仅显示“导航”，与现有文档界面使用相同的灰色样式，切换导航窗格且同步视图选项。方向键仅在阅读界面接管，不拦截文本输入、下拉选择、规则对话框与文件页，也不接管带 Ctrl / Command / Alt 的组合键。

翻屏使用 Range.getClientRects 获取已排版文本行，向后翻将末尾两条完整文字行放到新视口顶部，向前翻将开头两条完整文字行放到新视口底部。字号、行距、字体与缩放变化都会反映在实际行矩形中。首尾会限制到文档边界；若当前视口不足三行，按视口高度和实际行高计算可前进的距离。

导入 TTF 经本机选择器读取，校验大小、TrueType 标志、表目录与表边界，按文件内容哈希去重后复制到应用数据目录。渲染器通过固定 IPC 接口获取二进制数据，再由 FontFace 加载并注册；加载失败的新字体会撤销保存。启动时先恢复字体，再打开上次文档，以保留已选字体。更换字体后等待 document.fonts.ready，重新测量虚拟页并恢复字符位置。

字体加载参考：[FontFace 构造器](https://developer.mozilla.org/en-US/docs/Web/API/FontFace/FontFace)、[FontFaceSet.ready](https://developer.mozilla.org/en-US/docs/Web/API/FontFaceSet/ready)。

连续排版回归测试会直接测量相邻分块的几何接缝、标题前的段间距和文末尾部留白，并继续验证两行重叠翻读。翻读通过虚拟列表的滚动接口发起，避免旧定位任务与高度重测覆盖新的翻读目标。
