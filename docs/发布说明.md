# 构建与发布

## 构建产物

```sh
npm ci
npm test
npm run test:e2e
```

按目标平台构建：

| 命令 | 构建环境 | 产物 |
| --- | --- | --- |
| `npm run pack:mac` | macOS | Apple Silicon DMG、ZIP |
| `npm run pack:win` | Windows x64 | NSIS 安装器 EXE、免安装 ZIP |
| `npm run pack:win:zip` | macOS 或 Windows | Windows x64 免安装 ZIP |

所有构建结果位于 `release/`。`mac-arm64/` 与 `win-unpacked/` 是当前运行时目录；`archive/v版本号/` 可用于本机归档旧版安装包，均不提交到 Git。

开发者可执行 `node scripts/smoke-packaged.mjs` 检查已打包的本机应用。该脚本使用独立临时数据，不影响日常阅读进度。

## GitHub Actions

- `ci.yml`：对 `main` 分支提交和 Pull Request 运行单元测试、生产构建及 macOS / Windows 端到端测试。
- `build.yml`：手动执行或推送 `v*` 标签时，构建两个平台、检查打包结果并归档安装包。
- 标签构建全部成功后，发布工作流将安装包与 SHA-256 校验文件附到同名 GitHub Release。

发布新版本时：

1. 更新 `package.json` 和 `package-lock.json` 的版本。
2. 更新 `CHANGELOG.md` 和 `docs/releases/v版本号.md`。
3. 运行本地验证，提交后推送主分支。
4. 创建并推送与包版本一致的标签，例如 `v1.1.1`。
5. 检查 Actions、Release 资产和下载链接。

工作流只使用 GitHub 提供的临时仓库令牌上传发布文件，不需要提交个人令牌。macOS 当前采用 ad-hoc 签名，Windows 不做商业发行签名；正式签名与 Apple 公证可使用维护者自己的证书，通过 Actions secrets 配置，切勿放入仓库。
